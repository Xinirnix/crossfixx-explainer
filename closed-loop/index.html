How the controller lands a piezo stage

closed loop · tuning

The motor on its own only knows phase and amplitude: phase sets the direction, amplitude sets the speed. The controller closes the loop. Every 33 µs it reads the encoder, compares the count with where the stage should be, and turns that error into a new amplitude and phase. Far from the target it uses one set of gains, close to it another.

Once the stage is within PTOL encoder counts of the target, the controller switches the drive off and raises position reached. The preloaded tip then clamps the strip, so the stage holds its position with no power. If it can't get inside PTOL within TOUT ms, the looser PTO2 becomes the tolerance so it doesn't keep vibrating around the target.

    Symptoms and what to change

    Each row runs the symptom, then the change the manual points to. Quotes are from Xeryon's Controller & Connection Manual (rev 3.26, §13 and §14).

    From Xeryon's manual

    • Two zones, symmetric around the target, in encoder units. Error < ZON1 uses FREQ and PROP. Error > ZON2 uses FRQ2 and PRO2. In between the values are interpolated.
    • Within ±PTOL "the control is switched off and the 'position reached' flag is raised". PTO2 takes over if PTOL isn't reached within TOUT (default 50 ms).
    • DUCO = 1 uses amplitude in the loop; DUCO = 0 uses a fixed 50 % amplitude.
    • The following error is limited by ELIM; beyond it the controller goes to safe mode with the motor off.
    • Frequency "a few kHz above the resonant frequency often leads to a more relaxed control with better 'landing'". Too high gives "very limited force", too low "unstable behaviour".
    • Higher proportional factors react more strongly but can cause "instability or noisy operation". Lower ones give "a more sluggish motion response".
    • Payload: "For every 100g of mass you add, increase the MASS parameter with 100", then "halve the values of PROP and PRO2".
    • Encoders: 1250, 312, 78, 5 and 1 nm per count.

    Our model (editable in src/closed-loop/sim.js)

    • Drive = (PROP·error − MASS·KD·speed) / 30000, clamped to ±1. Xeryon doesn't publish the internal law or the gain scaling, so the scale is chosen so the defaults land cleanly.
    • Drive becomes amplitude, its sign becomes the ±90° phase. The tip then moves 2·A·sin φ per cycle, the same tip equation as the CrossFixx page.
    • The tip pushes with at most 4 N × amplitude × |sin φ|. Mass and load decide how fast the stage follows. With the drive off, a 4 N preload holds the stage (self-locking).
    • An example resonance of 166 kHz (as on the CrossFixx page; real stages range widely), Q = 30, softening by 5 kHz at full amplitude. The manual's defaults search 165–175 kHz and drive at FREQ = 170 kHz, a few kHz above it. Mode ring-up time Q/(πf) ≈ 57 µs is the main loop delay.
    • MASS caps the planned acceleration at 2 N / (carriage + MASS g) and adds speed damping. This is our reading of MASS, not Xeryon's code.
    • Not modelled: DLAY, PHAC, offsets, scanning, index search, thermal drift.
